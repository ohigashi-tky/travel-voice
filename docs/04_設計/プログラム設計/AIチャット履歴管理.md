# AIチャット履歴管理

## 概要

観光ガイドアプリケーションにおけるAIチャット機能の会話履歴管理システム。OpenRouter APIを使用した観光情報特化型AIとの対話履歴を効率的に管理する。

## アーキテクチャ

### フロントエンド層
- **Pinia Store**: `aiChat.ts`による状態管理
- **ローカルストレージ**: ブラウザでの会話履歴永続化
- **Vue.js**: リアクティブなUI更新

### バックエンド層
- **Nuxt.js Server API**: `/api/chat`エンドポイント
- **OpenRouter API**: 外部AI サービス連携
- **プロンプトエンジニアリング**: 観光情報特化型システムプロンプト

## データ構造

### メッセージ形式
```typescript
interface ChatMessage {
  role: 'user' | 'assistant' | 'questions'
  content: string
  questions?: string[]
  audioGuideSpots?: Array<{id: number, name: string}>
}
```

### 会話履歴制限
- **API送信**: 最大12メッセージ（過去の文脈保持）
- **文脈抽出**: 最新4メッセージから観光地名抽出
- **ローカル保存**: 全履歴をブラウザに永続保存

## プロンプト構築

### システムプロンプト特徴
- **文字数制限**: 700文字以内での簡潔な回答
- **マークダウン形式**: 構造化された読みやすい出力
- **関連質問生成**: 具体的な場所名を含む実用的な質問3つ

### 文脈情報抽出
```javascript
// 観光地名の正規表現パターン
const locationMatches = content.match(
  /[ぁ-ん一-龯ー]+[城|寺|神社|公園|駅|橋|山|島|湖|川|通り|街|区|市|府|県|タワー|美術館|博物館|水族館|動物園]/g
)
```

### 指示語禁止ルール
- 「この場所」「ここ」「そこ」等の曖昧な表現を禁止
- 必ず具体的な固有名詞を使用
- 例: ❌「この場所の営業時間は？」→ ✅「清水寺の拝観時間は？」

## 状態管理

### Pinia Store機能
- **メッセージ追加**: `addUserMessage()`, `addAssistantMessage()`
- **API通信**: `sendMessage()`での非同期処理
- **履歴クリア**: `clearMessages()`
- **永続化**: `saveToStorage()`, `loadFromStorage()`

### エラーハンドリング
- **API接続エラー**: ユーザーフレンドリーなエラーメッセージ
- **JSON解析エラー**: 適切なフォールバック処理
- **ローカルストレージエラー**: コンソール警告での非侵入的処理

## API設計

### リクエスト形式
```typescript
{
  message: string,
  conversation: Array<{role: string, content: string}>
}
```

### レスポンス形式
```typescript
{
  content: string,
  model: string,
  usage: object
}
```

### パフォーマンス最適化
- **温度設定**: 0.7での適度な創造性
- **最大トークン**: 1000トークンでの効率的な回答
- **タイムアウト**: 60秒での適切な応答時間

## セキュリティ

### APIキー管理
- **環境変数**: `OPENROUTER_API_KEY`での安全な管理
- **ランタイム設定**: Nuxt.jsのuseRuntimeConfig()使用
- **エラー隠蔽**: 本番環境での詳細エラー情報非表示

### データ保護
- **ローカル保存のみ**: サーバーサイドでの会話履歴非保存
- **セッション管理**: ブラウザ単位での履歴分離
- **データ検証**: 入力値の適切なバリデーション

## 運用考慮事項

### メンテナンス性
- **モジュール分離**: Store、API、UIの責務分離
- **型安全性**: TypeScriptによる型定義
- **ログ出力**: デバッグ用の適切なコンソール出力

### スケーラビリティ
- **ステートレス設計**: サーバーサイドでの状態非保持
- **キャッシュ戦略**: 不要なAPI呼び出し削減
- **非同期処理**: ノンブロッキングなUI更新
