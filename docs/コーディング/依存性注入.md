# 依存性注入（Dependency Injection）解説

## 📚 基本概念

**依存性注入（Dependency Injection, DI）**は、クラスが必要とする他のクラス（依存関係）を外部から渡す設計パターンです。

### 🎯 目的
- クラス間の結合度を下げる
- テストしやすいコードを作る
- 保守性・拡張性を向上させる

---

## 💡 基本的な理解

### ❌ 悪い例（依存性注入なし）
```php
class AudioGuideController 
{
    public function synthesize($text) 
    {
        // クラス内部で直接インスタンス化 → 密結合
        $pollyService = new PollyService();
        return $pollyService->synthesize($text);
    }
}
```

**問題点**:
- `PollyService`と強く結合している
- テスト時にモックに置き換えできない
- `PollyService`の変更が`AudioGuideController`に影響する

### ✅ 良い例（依存性注入あり）
```php
class AudioGuideController 
{
    private PollyService $pollyService;
    
    // コンストラクタで依存関係を注入
    public function __construct(PollyService $pollyService)
    {
        $this->pollyService = $pollyService;
    }
    
    public function synthesize($text) 
    {
        return $this->pollyService->synthesize($text);
    }
}
```

**利点**:
- `PollyService`との結合度が低い
- テスト時に簡単にモックに置き換え可能
- 外部から異なる実装を注入できる

## 🔍 このプロジェクトでの実例

### 1. AudioGuideController での実装

```php
<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Services\PollyService;
use Illuminate\Http\Request;
use Illuminate\Http\JsonResponse;

class AudioGuideController extends Controller
{
    private PollyService $pollyService;

    /**
     * 依存性注入 - PollyServiceを外部から注入
     */
    public function __construct(PollyService $pollyService)
    {
        $this->pollyService = $pollyService;
    }

    /**
     * 利用可能な音声一覧を取得
     */
    public function getAvailableVoices(): JsonResponse
    {
        try {
            // 注入されたサービスを使用
            $voices = $this->pollyService->getAvailableVoices();
            
            return response()->json([
                'success' => true,
                'data' => [
                    'voices' => $voices,
                    'recommended' => ['Takumi', 'Tomoko', 'Mizuki', 'Kazuha'],
                ],
            ]);
        } catch (\Exception $e) {
            return response()->json([
                'success' => false,
                'message' => '音声一覧の取得に失敗しました',
            ], 500);
        }
    }

    /**
     * 音声合成実行
     */
    public function synthesize(Request $request): JsonResponse
    {
        // 注入されたサービスを使用
        return $this->pollyService->synthesize($request->input('text'));
    }
}
```

## 🎯 メリット・デメリット

### ✅ メリット

#### 1. **テストしやすさ**
```php
// テスト時にモックを注入可能
class AudioGuideControllerTest extends TestCase
{
    public function testGetAvailableVoices()
    {
        // モックサービスを作成
        $mockPollyService = $this->createMock(PollyService::class);
        $mockPollyService->method('getAvailableVoices')
                         ->willReturn(['Takumi', 'Tomoko']);
        
        // モックを注入してテスト
        $controller = new AudioGuideController($mockPollyService);
        $result = $controller->getAvailableVoices();
        
        $this->assertTrue($result->getData()->success);
    }
}
```

#### 2. **柔軟性**
```php
// 本番環境: 実際のPollyService
$controller = new AudioGuideController(new PollyService());

// テスト環境: ダミーのPollyService
$controller = new AudioGuideController(new DummyPollyService());

// 開発環境: ログ出力するPollyService
$controller = new AudioGuideController(new LoggingPollyService());
```

#### 3. **保守性**
- `PollyService`の実装変更が`AudioGuideController`に影響しない
- 各クラスの責任が明確に分離される
- 新しいサービス実装への切り替えが容易

#### 4. **再利用性**
```php
// 同じサービスを複数のコントローラーで使用
$pollyService = new PollyService();

$audioController = new AudioGuideController($pollyService);
$voiceController = new VoiceController($pollyService);
$speechController = new SpeechController($pollyService);
```

### ⚠️ デメリット

#### 1. **複雑性の増加**
- 設定が複雑になる場合がある
- 依存関係の管理が必要
- 初期学習コストがかかる

#### 2. **実行時エラーの可能性**
- 注入するクラスが見つからない場合のエラー
- 循環依存の問題

#### 3. **パフォーマンス**
- わずかなオーバーヘッド（通常は無視できるレベル）

## 🔧 Laravelでの自動解決

Laravelは**サービスコンテナ**で依存性注入を自動化します：

### 1. 自動解決の仕組み
```php
// Laravelが自動で以下を実行
app()->bind(PollyService::class, function() {
    return new PollyService();
});

// コントローラー呼び出し時、Laravelが自動注入
$pollyService = app()->make(PollyService::class);
$controller = new AudioGuideController($pollyService);
```

### 2. サービスプロバイダーでのカスタムバインド
```php
// app/Providers/AppServiceProvider.php
public function register()
{
    $this->app->bind(PollyService::class, function ($app) {
        return new PollyService(
            config('services.polly.key'),
            config('services.polly.secret')
        );
    });
}
```

### 3. インターフェースを使った抽象化
```php
// より柔軟な設計
interface AudioSynthesizerInterface
{
    public function synthesize(string $text): string;
}

class PollyService implements AudioSynthesizerInterface
{
    public function synthesize(string $text): string
    {
        // Amazon Polly実装
    }
}

class GoogleTextToSpeechService implements AudioSynthesizerInterface
{
    public function synthesize(string $text): string
    {
        // Google TTS実装
    }
}

// コントローラーはインターフェースに依存
class AudioGuideController extends Controller
{
    public function __construct(AudioSynthesizerInterface $audioSynthesizer)
    {
        $this->audioSynthesizer = $audioSynthesizer;
    }
}
```

## 🚀 実践的な活用例

### 1. 音声サービスの切り替え
```php
// 設定で音声サービスを切り替え
// config/audio.php
return [
    'default_synthesizer' => env('AUDIO_SYNTHESIZER', 'polly'),
    
    'synthesizers' => [
        'polly' => PollyService::class,
        'google' => GoogleTextToSpeechService::class,
        'mock' => MockAudioSynthesizer::class,
    ],
];

// サービスプロバイダー
public function register()
{
    $this->app->bind(AudioSynthesizerInterface::class, function ($app) {
        $synthesizer = config('audio.default_synthesizer');
        $class = config("audio.synthesizers.{$synthesizer}");
        
        return $app->make($class);
    });
}
```

### 2. キャッシュ戦略の注入
```php
interface CacheInterface
{
    public function get(string $key);
    public function put(string $key, $value, int $ttl);
}

class AudioGuideController
{
    public function __construct(
        AudioSynthesizerInterface $synthesizer,
        CacheInterface $cache
    ) {
        $this->synthesizer = $synthesizer;
        $this->cache = $cache;
    }
    
    public function synthesize(Request $request)
    {
        $text = $request->input('text');
        $cacheKey = 'audio_' . md5($text);
        
        // キャッシュから取得を試行
        if ($audio = $this->cache->get($cacheKey)) {
            return response()->json(['audio_url' => $audio]);
        }
        
        // 音声合成実行
        $audio = $this->synthesizer->synthesize($text);
        
        // キャッシュに保存
        $this->cache->put($cacheKey, $audio, 3600);
        
        return response()->json(['audio_url' => $audio]);
    }
}
```

## 📝 ベストプラクティス

### 1. **単一責任の原則**
```php
// ✅ 良い例：各サービスが単一の責任を持つ
class PollyService  // 音声合成のみ担当
class CacheService  // キャッシュのみ担当
class LogService    // ログのみ担当

// ❌ 悪い例：複数の責任を持つ
class AudioService  // 音声合成 + キャッシュ + ログ
```

### 2. **インターフェースの活用**
```php
// 抽象に依存し、具象に依存しない
interface AudioSynthesizerInterface {}
interface CacheInterface {}
interface LoggerInterface {}
```

### 3. **適切なスコープ管理**
```php
// シングルトン：状態を持たないサービス
$this->app->singleton(ConfigService::class);

// 通常のバインド：毎回新しいインスタンス
$this->app->bind(EmailService::class);
```
